A few things
you might be wondering.

Can I use a server I already have?

Yes, if it meets the mail server requirements and has enough available resources. The setup prompt tells your agent to inspect existing services and check for conflicts before making changes. See what to prepare →

Will this replace my existing email?

It depends on the domain you choose. Changing a domain’s MX records changes where its incoming mail goes. Your agent should review existing routing and ask before changing it. A separate domain or subdomain can keep the new mail service separate.

Can I open the inbox myself?

Yes. Roundcube gives you a browser inbox where you can read and reply yourself. Its mailbox password is separate from the scoped key your agent uses.

Can an agent read mail without permission to send?

Yes. Give it read-only access, or explicitly add sending permission. Keys are scoped to an inbox and can expire or be revoked from the dashboard.

Will email always arrive in the recipient’s inbox?

Inbox placement is not guaranteed. Domain authentication, server reputation and recipient filters all matter. During setup, verify sending and receiving with an external inbox, and check Spam or Junk too. “Submitted” means the mail server accepted a message; it does not prove recipient delivery.

Does my agent automatically respond to every email?

No. Connecting MCP makes mailbox tools available when your agent uses them. Automatic monitoring and replies need an agent workflow and an explicit policy. Treat incoming email as untrusted content, and grant only the permissions that workflow needs.

What will I have to do during setup?

Choose your address and server, provide access, and handle sign-in codes or account approvals. Your agent pauses for purchases or changes to existing mail routing. At the end, confirm a test email and reply so it can verify both directions.
