Get the Cloudflare Client ID and Client Secret, then make them available to the computer running your agent. These are needed when Cloudflare Access protects your Hermesaki MCP endpoint.

Your agent can do the browser steps with your signed-in Cloudflare tab. You handle sign-in and any account approvals. Already saved a valid service token? Reuse its private saved credentials instead of creating another.

Create the service token

  1. In Cloudflare, open Zero Trust → Access controls → Service credentials → Service Tokens.
  2. Select Create Service Token, enter a recognizable name and choose an expiry.
  3. Select Generate token. Save both the Client ID and Client Secret in your secret manager. The secret is displayed only once; if lost, rotate it or create a replacement and update your clients.
Screenshot: create a service token

Authorize it for your MCP hostname

Open the Access application covering your Hermesaki API hostname. Add a policy with Action: Service Auth and Include: Service Token, select your specific token, and save the policy on that application. Keep the owner's email Allow policy for browser sign-in. Creating a token alone does not grant access. Cloudflare service-token reference ↗

Match the values to the variables

Environment variableWhere the value comes from
CF_ACCESS_CLIENT_IDCloudflare service token → Client ID
CF_ACCESS_CLIENT_SECRETCloudflare service token → Client Secret
HERMESAKI_MAILBOX_KEYHermesaki → Agent access → the selected mailbox's scoped access key

The two Cloudflare variables become the CF-Access-Client-Id and CF-Access-Client-Secret request headers. The mailbox key becomes Authorization: Bearer …. Your Cloudflare DNS API token, mailbox password and browser session are different credentials.

Load them on your computer

Run the block for your shell locally. Paste the values at the prompts; secret input is hidden and the pasted values do not become shell commands in history. These commands set variables for the current terminal and programs launched from it.

macOS / Linux — Bash or Zsh 
printf 'Cloudflare Client ID: '
IFS= read -r CF_ACCESS_CLIENT_ID
printf 'Cloudflare Client Secret (hidden): '
IFS= read -rs CF_ACCESS_CLIENT_SECRET
printf '\nMailbox access key (hidden): '
IFS= read -rs HERMESAKI_MAILBOX_KEY
printf '\n'
export CF_ACCESS_CLIENT_ID CF_ACCESS_CLIENT_SECRET HERMESAKI_MAILBOX_KEY

Start grok, codex, claude or opencode from this same terminal after adding its MCP configuration.

Windows — PowerShell 
$env:CF_ACCESS_CLIENT_ID = Read-Host 'Cloudflare Client ID'
$secret = Read-Host 'Cloudflare Client Secret' -AsSecureString
$env:CF_ACCESS_CLIENT_SECRET = [System.Net.NetworkCredential]::new('', $secret).Password
$mailboxKey = Read-Host 'Mailbox access key' -AsSecureString
$env:HERMESAKI_MAILBOX_KEY = [System.Net.NetworkCredential]::new('', $mailboxKey).Password
Remove-Variable secret, mailboxKey

Launch your CLI agent from this PowerShell window. Closing it removes these session variables.

Keep the setup available after restarting

Keep the credentials in your secret manager. Ask your agent to configure a private launcher or your app's supported secret settings so the variables load whenever that app starts. A random .env file is not automatically loaded by every MCP client.

For Windows user-level environment variables, run the following after entering the values above. This stores them in your Windows user environment as plaintext; use your secret manager instead if available. Restart the agent app afterward.

[Environment]::SetEnvironmentVariable('CF_ACCESS_CLIENT_ID', $env:CF_ACCESS_CLIENT_ID, 'User')
[Environment]::SetEnvironmentVariable('CF_ACCESS_CLIENT_SECRET', $env:CF_ACCESS_CLIENT_SECRET, 'User')
[Environment]::SetEnvironmentVariable('HERMESAKI_MAILBOX_KEY', $env:HERMESAKI_MAILBOX_KEY, 'User')

For macOS/Linux, a private shell launcher can load these values from a secret manager or an owner-readable file outside your repository before starting the agent. Have your agent preserve existing configuration and handle shell quoting. Do not paste secrets into a setup prompt or commit them with your project.

Connect your app and check it

Open the MCP client guide, select your app and merge its example configuration. Environment-reference syntax differs between clients.

Desktop apps launched from the Dock or Start menu may not inherit terminal variables. Fully quit and relaunch through the configured launcher, or use the app's supported private header settings. Refresh its MCP connection, then ask it to call list_folders with your exact inbox ID. Check that it returns folders without sending mail.

A Cloudflare login page or 403 usually means the service credentials or policy need checking. A Hermesaki 401 usually means the mailbox key is missing or invalid. Check whether variables are present without printing their values; do not disable Access to make the connection work.
